# Maintainability

- One of the main tasks after building a [[Distributed System]] is to keep the system up and running by finding and fixing bugs, adding new functionalities, keeping the system's platform updated and ensuring smooth system operations
- 3 main aspects:
	- Operability:
		- Ease at which we can ensure system's smooth operational running under normal circumstances and achieve normal conditions under a fault
	- Lucidity:
		- Refers to the simplicity of the code. Simpler the code base the easier it is to understand and maintain it
	- Modifiability:
		- Capability of the system to integrate modified, new, and unforeseen features without any hassle
- Also the probability that the service will restore its functions within a specified time of fault occurence
	- M
- Ie M of 95% means over an hour probability of restoring the component is .95
- Can use [[Mean Time To Repair]] to measure it
$$
MTTR = \frac{Total Maintenance Time}{Total Number of Repairs}
$$
	- Average time to repair and restore a failed component
	- Lower teh value means more maintainability
